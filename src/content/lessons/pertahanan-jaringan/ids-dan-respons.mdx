Firewall mencegah, tapi tidak ada pertahanan yang sempurna. Karena itu organisasi juga harus bisa **mendeteksi** serangan dan **merespons** dengan cepat. Fondasinya adalah **log**.

## Log penting di Linux

| File | Isi |
|---|---|
| `/var/log/auth.log` | login, sudo, SSH (berhasil & gagal) |
| `/var/log/syslog` | pesan sistem umum |
| `/var/log/kern.log` | pesan kernel, termasuk aturan `iptables -j LOG` |
| `/var/log/nginx/access.log` | setiap request ke web server |

Kamu sudah punya alat untuk membacanya sejak Modul 1:

```bash
grep "Failed password" /var/log/auth.log | wc -l     # berapa banyak?
grep "Failed password" /var/log/auth.log | tail      # yang terbaru
grep 203.0.113.66 /var/log/auth.log                  # aktivitas IP tertentu
```

## IDS & IPS

- **IDS (Intrusion Detection System)** — memantau lalu lintas/log dan **memberi peringatan** jika ada pola mencurigakan (port scan, brute force, signature malware). Contoh: Snort, Suricata, Zeek.
- **IPS (Intrusion Prevention System)** — seperti IDS, tapi juga **memblokir** secara otomatis.
- **SIEM** — mengumpulkan log dari banyak sistem ke satu tempat untuk dianalisis (contoh: Wazuh, Elastic, Splunk).

Pola yang biasa dideteksi:

| Pola | Kemungkinan |
|---|---|
| SYN ke puluhan port berbeda dari satu IP dalam beberapa detik | port scan |
| Puluhan `Failed password` dari satu IP, username bervariasi | brute force |
| Login berhasil pukul 03.00 dari negara lain | akun dibobol |
| ARP reply tak diminta, MAC gateway berubah | ARP spoofing |

## fail2ban: respons otomatis

**fail2ban** membaca log dan memblokir IP yang gagal login berkali-kali dengan menambahkan aturan firewall secara otomatis — persis yang akan kamu lakukan secara manual di lab:

```text
1. baca auth.log → 5 kali gagal dari 203.0.113.66 dalam 10 menit
2. iptables -I INPUT -s 203.0.113.66 -j REJECT
3. hapus blokir setelah 1 jam (bantime)
```
