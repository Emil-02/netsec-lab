**Cross-Site Scripting (XSS)** terjadi ketika aplikasi menampilkan input pengguna di halaman HTML **tanpa di-escape**, sehingga penyerang bisa menyisipkan **skrip** yang kemudian dijalankan oleh **browser pengunjung lain**.

Jika SQL injection menyerang **database di server**, XSS menyerang **pengguna** aplikasi.

## Kenapa berbahaya?

Skrip yang berjalan di halaman sebuah situs punya akses yang sama dengan situs itu sendiri. Penyerang dapat:

- 🍪 **Mencuri cookie sesi** → mengambil alih akun korban tanpa tahu password-nya
- 🎭 Melakukan aksi **atas nama korban** (mengirim pesan, mengubah email, transfer)
- 🎣 Mengganti tampilan halaman dengan **form login palsu** (phishing di domain asli!)
- ⌨️ Merekam apa yang diketik korban

## Jenis-jenis XSS

### 1. Reflected XSS

Input dari URL langsung "dipantulkan" ke halaman:

```text
https://forum.lab/cari?q=<script>…</script>
→ "Hasil pencarian untuk: <script>…</script>"
```

Penyerang harus **membujuk korban mengklik** link berbahaya (lewat email, chat, media sosial).

### 2. Stored XSS

Payload **disimpan** di server (komentar, profil, buku tamu) lalu ditampilkan ke **setiap pengunjung**. Jauh lebih berbahaya karena korbannya bisa ribuan orang, termasuk admin.

### 3. DOM-based XSS

Celah ada di **JavaScript sisi client** yang memasukkan data (misalnya dari URL) ke halaman dengan `innerHTML`. Payload tidak pernah disisipkan server ke dalam HTML, sehingga sering lolos dari pemeriksaan di sisi server.

## Tidak hanya tag `<script>`

Skrip bisa disisipkan lewat banyak cara, misalnya **event handler** atribut HTML:

```html
<img src=x onerror=alert(1)>
<a href="javascript:alert(1)">klik</a>
```

Karena itu, memblokir kata "script" saja tidak cukup.

## Pertahanan

### Output encoding (escaping) — pertahanan utama

Ubah karakter khusus HTML menjadi entitas sebelum ditampilkan:

| Karakter | Menjadi |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;` |
| `'` | `&#39;` |
| `&` | `&amp;` |

Hasilnya, `<script>` tampil sebagai **teks biasa** di layar, bukan dieksekusi. Framework modern (React, Vue, template engine) melakukan ini **secara otomatis** — celah biasanya muncul saat developer menonaktifkannya (`dangerouslySetInnerHTML`, `v-html`, `|safe`).

Escaping harus **sesuai konteks**: tabel di atas untuk isi HTML dan atribut. Untuk URL di `href`/`src`, escaping saja tidak cukup — `javascript:alert(1)` tidak mengandung karakter berbahaya sama sekali. Validasi bahwa URL diawali skema yang aman (`https://`, `http://`, atau path relatif).

### Lapisan tambahan

- 🛡️ **Content Security Policy (CSP)** — header yang memberi tahu browser skrip mana yang boleh dijalankan
- 🍪 **Cookie `HttpOnly`** — cookie sesi tidak bisa dibaca JavaScript, sehingga tidak bisa dicuri lewat XSS
- 🧹 **Sanitasi HTML** dengan library tepercaya jika pengguna memang boleh memakai format (tebal, miring)
- ✅ **Validasi input** sesuai konteks
