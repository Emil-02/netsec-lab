Manusia lebih mudah mengingat `netseclab.id` daripada `203.0.113.80`. **DNS (Domain Name System)** adalah "buku telepon Internet" yang menerjemahkan **nama domain** menjadi **alamat IP**.

Semua pertanyaan ini biasanya memakai **UDP port 53** dan selesai dalam beberapa milidetik.

## Jenis record DNS

| Record | Fungsi | Contoh |
|---|---|---|
| **A** | nama → IPv4 | `web.kantor.lab → 10.0.0.80` |
| **AAAA** | nama → IPv6 | `→ 2001:db8::80` |
| **CNAME** | alias ke nama lain | `intranet.kantor.lab → web.kantor.lab` |
| **MX** | server email domain | `kantor.lab → mail.kantor.lab` |
| **TXT** | teks bebas (SPF, verifikasi) | `"v=spf1 mx -all"` |
| **NS** | nameserver pengelola domain | `→ ns1.kantor.lab` |

## Konfigurasi DNS di Linux

```bash
$ cat /etc/resolv.conf
nameserver 10.0.0.53

$ cat /etc/hosts
127.0.0.1   localhost
10.0.0.80   web.lokal
```

Urutan pencarian: **/etc/hosts dulu**, baru **DNS server**.

## Alat-alat DNS

```bash
nslookup web.kantor.lab              # sederhana
nslookup web.kantor.lab 10.0.0.53    # tanya ke server tertentu
dig netseclab.id                     # detail lengkap
dig kantor.lab MX                    # record tipe tertentu
dig +short netseclab.id              # jawaban saja
host netseclab.id                    # ringkas
```

## Troubleshooting: "internetnya mati!"

Jika `ping 10.0.0.80` berhasil tapi `ping web.kantor.lab` gagal dengan *Temporary failure in name resolution*, jaringan sebenarnya baik-baik saja — **masalahnya di DNS**. Periksa `/etc/resolv.conf` dan coba tanya DNS server secara langsung.

<Callout type="danger" title="DNS dan keamanan">
DNS klasik **tidak terenkripsi dan tidak diautentikasi**. Penyerang bisa menyadap nama situs yang kamu kunjungi, atau melakukan **DNS spoofing**: memberikan jawaban palsu agar kamu diarahkan ke situs phishing. Mengubah `/etc/hosts` juga trik favorit malware. Pertahanan modern: **DNSSEC**, **DNS over HTTPS (DoH)**, dan **DNS over TLS (DoT)**.
</Callout>
