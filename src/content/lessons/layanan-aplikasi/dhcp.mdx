Di Modul 4 kamu mengatur IP, subnet mask, dan gateway secara manual. Bayangkan harus melakukannya untuk 500 laptop di kampus — dan memastikan tidak ada yang bentrok! Untungnya ada **DHCP (Dynamic Host Configuration Protocol)** yang membagikan konfigurasi jaringan **secara otomatis**.

## Apa yang diberikan DHCP?

- ✅ **Alamat IP** + subnet mask
- ✅ **Default gateway**
- ✅ **DNS server**
- ✅ **Lease time** — berapa lama alamat itu boleh dipakai sebelum harus diperpanjang

DHCP server biasanya berjalan di **router** (rumah/kantor kecil) atau di server khusus (jaringan besar).

Kenapa memakai broadcast? Karena laptop **belum punya IP** dan **belum tahu alamat DHCP server** — satu-satunya cara adalah "berteriak" ke seluruh LAN.

## Di Linux

```bash
sudo dhclient -v eth0     # minta IP via DHCP
sudo dhclient -r eth0     # lepaskan (release) IP
ip a                      # cek IP yang didapat
ip route                  # cek gateway yang didapat
cat /etc/resolv.conf      # cek DNS yang didapat
```

## DHCP vs IP statis

| | DHCP (dinamis) | Statis |
|---|---|---|
| Cocok untuk | laptop, HP, PC pengguna | server, printer, router |
| Kelebihan | otomatis, tanpa bentrok | alamat selalu sama, mudah ditemukan |
| Kekurangan | alamat bisa berubah | harus diatur manual satu per satu |

Banyak admin memakai **DHCP reservation**: server DHCP selalu memberi IP yang sama untuk MAC tertentu (misalnya printer).

<Callout type="danger" title="Serangan terhadap DHCP">
- **Rogue DHCP server**: penyerang menjalankan DHCP server palsu di LAN dan memberikan **gateway/DNS milik penyerang** ke korban → semua lalu lintas korban lewat penyerang (man-in-the-middle).
- **DHCP starvation**: penyerang meminta ribuan IP dengan MAC palsu sampai pool habis, sehingga pengguna sah tidak mendapat IP.

Pertahanannya: fitur **DHCP snooping** di switch, yang hanya mengizinkan balasan DHCP dari port tepercaya.
</Callout>
