**TCP (Transmission Control Protocol)** adalah protokol transport yang **andal**: data dijamin sampai, berurutan, dan tanpa duplikat. Dipakai oleh web, email, SSH, dan hampir semua aplikasi yang tidak boleh kehilangan data.

Agar bisa andal, TCP harus memastikan kedua pihak siap sebelum mengirim data. Proses ini disebut **three-way handshake**.

## Flag TCP

| Flag | Arti |
|---|---|
| **SYN** | *synchronize* — minta membuka koneksi |
| **ACK** | *acknowledge* — konfirmasi data/segmen yang sudah diterima |
| **PSH** | *push* — segera serahkan data ke aplikasi |
| **FIN** | *finish* — menutup koneksi dengan sopan |
| **RST** | *reset* — tolak/putus koneksi secara paksa |

## Port tertutup → RST

Jika client mengirim SYN ke port yang tidak ada layanannya, server langsung membalas **RST, ACK**: *"Tidak ada siapa-siapa di sini."* Itulah yang dilihat aplikasi sebagai `Connection refused`.

## Nomor urut (sequence) dan ACK

Setiap byte data diberi nomor urut. Penerima membalas dengan nomor ACK = *byte berikutnya yang ia harapkan*. Jika ada segmen hilang, pengirim tahu dan mengirim ulang (**retransmission**). Inilah yang membuat TCP andal.

<Callout type="danger" title="Serangan di level TCP">
- **SYN flood**: penyerang mengirim ribuan SYN tanpa pernah menyelesaikan handshake, sehingga server kehabisan memori untuk menyimpan koneksi setengah-terbuka (serangan DoS).
- **Port scanning**: `nmap -sS` mengirim SYN ke banyak port; balasan SYN-ACK = terbuka, RST = tertutup, diam = difilter.
</Callout>
